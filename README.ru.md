Небольшой Python-инструментарий для выделения границ и воспроизводимый бенчмарк. В пакете **семь** готовых к использованию детекторов с единым API: классические полутоновые (**Sobel**, **Prewitt**, **Canny**), цветовые (**структурный тензор Ди Дзензо**, **цветной Canny** на его основе, **multichannel Sobel**) и **`vector_lighting`** — метод, выведенный здесь из модели «виртуального освещения» RGB-каналов.

> ### ⚠️ Честный статус метода `vector_lighting`
> Проект начинался как попытка оригинального цветового детектора границ. Строгое сравнение с правильным **цветовым** эталоном — **структурным тензором Ди Дзензо (1986)** — показало:
> - **Ядро `vector_lighting` математически эквивалентно цветовому структурному тензору Ди Дзензо.** С отключённым height-членом его карта отклика ранг-идентична Di Zenzo (Spearman ρ ≈ 0.99 на реальных изображениях, 1.00 на изолюминантных тестах). Конструкция «виртуальное освещение + перестановки каналов» — это **альтернативный вывод уже существующего оператора**.
> - Единственная отличительная часть — асимметричный по каналам *height*-член — возмущает результат лишь на ~2–3% и **не улучшает** точность на обычных RGB (на BSDS500 слегка ухудшает).
> - Преимущество «цветочувствительности» над полутоновым Canny **реально, но не уникально** — у Di Zenzo оно тоже есть.
>
> Таким образом, `vector_lighting` — **не** превосходящий новый детектор. Этот репозиторий правильнее понимать как **бенчмарк и независимый повторный вывод**, а не как заявление о новизне. Алгебраическое доказательство эквивалентности — в [`docs/equivalence.md`](docs/equivalence.md); эмпирическая проверка воспроизводится командой `python tests/correspondence_analysis.py`.

## Что внутри

- **Полутоновые детекторы:** Sobel, Prewitt, Canny (реализации на NumPy/SciPy).
- **Цветовые детекторы:** структурный тензор Ди Дзензо, цветной Canny на его основе, multichannel-Sobel и `vector_lighting`.
- **Воспроизводимый харнесс** (`tests/testing.py`): синтетика, тест ориентации/анизотропии, тест масштабирования, оценка на реальных изображениях BSDS500.
- **Анализ соответствия** (`tests/correspondence_analysis.py`), количественно показывающий эквивалентность `vector_lighting` ↔ Di Zenzo.

Все числа ниже воспроизводимы. Абсолютное время зависит от машины.

## 📊 Результаты бенчмарка

### Синтетика (F1, допуск 2 px, 256×256)

> ⚠️ **Эти числа не являются надёжным ранжированием.** См. предупреждение о «ничьих» под таблицей.

`python tests/testing.py --baseline-only`. Sobel/Prewitt/Di Zenzo бинаризуются по 95-му перцентилю.

| Изображение | Sobel | Canny | DiZenzo | VectorLight |
|-------------|:-----:|:-----:|:-------:|:-----------:|
| `checkerboard` | 0.000 | 0.958 | 0.505 | 0.933 |
| `concentric_circles` | 1.000 | 1.000 | 1.000 | 1.000 |
| `color_patches_equal_brightness` | 1.000 | 0.000 | 0.909 | 0.909 |
| `color_wheel` | 0.510 | 0.473 | 0.340 | 0.887 |
| `blurred_disk` | 1.000 | 1.000 | 1.000 | 1.000 |
| `gray_scale` | 1.000 | 1.000 | 0.000 | 0.000 |
| **Средний F1** | 0.752 | 0.739 | 0.626 | 0.788 |

**Почему они ненадёжны: ничьи на пороге.** Синтетические изображения содержат обширные области с одинаковой магнитудой градиента, поэтому тысячи пикселей попадают *ровно* на перцентильный порог и включаются либо исключаются все разом. Замена сравнения `>` на `>=` — выбор разрешения ничьих, лишённый физического смысла, — сдвигает F1 на величину до **0,45**:

| Изображение | Пикселей ровно на пороге | F1 при `>` | F1 при `>=` |
|---|:--:|:--:|:--:|
| `checkerboard` | 4690 (28,6 %) | 0,505 | **0,954** |
| `color_patches_equal_brightness` | 992 | 0,909 | 0,772 |
| `color_wheel` | 527 | 0,340 | 0,469 |
| Реальное фото (BSDS500) | 173 (0,11 %) | — | пренебрежимо |

По той же причине эти числа меняются при округлении на уровне 1e-16. **Выводы следует делать по результатам на реальных изображениях ниже**, где ничьих 0,11 % пикселей и числа устойчивы.

### Цветочувствительность (изолюминантные границы) — преимущество общее

Полосы из цветов равной яркости, 12 ориентаций (`python tests/testing.py --orientation`):

| Метод | F1 на изолюминантных границах |
|-------|:----------------------------:|
| VectorLight | ~0.99 |
| **DiZenzo** | **~0.99** |
| Canny | 0.000 |

Оба цветовых метода видят изолюминантные границы; полутоновый Canny — нет. Это исправленная версия прежнего заявления «уникально для нашего метода» — оно **не** уникально.

### Реальные изображения — BSDS500 (test-сплит, 200 изобр.)

`python tests/testing.py --bsds /путь/к/BSDS500`. GT — объединение аннотаторов, допуск 0.0075×диагональ, фиксированные пороги.

| Метод | F1 | Precision | Recall |
|-------|:--:|:---------:|:------:|
| **DiZenzo** | **0.575** | **0.654** | 0.531 |
| Canny | 0.566 | 0.482 | 0.774 |
| VL-default | 0.552 | 0.630 | 0.509 |
| Prewitt | 0.543 | 0.582 | 0.529 |
| Sobel | 0.541 | 0.577 | 0.530 |

На реальных фото Di Zenzo опережает `vector_lighting` (0.575 против 0.552). Все рукотворные детекторы существенно ниже современных обучаемых методов (BSDS ODS ≈ 0.83–0.84).

### Эквивалентность методов (`tests/correspondence_analysis.py`)

| Сравнение | Spearman ρ (структурные изобр.) | Смысл |
|---|:--:|---|
| VectorLight(α=0) ↔ DiZenzo | **0.99–1.00** | Ранг-идентичны ⇒ тот же оператор |
| height-член (α=1 vs α=0) | ~0.98 | Вносит лишь ~2–3% возмущения |

### Время выполнения — различия определяются конфигурацией, а не оператором

Все операторы теперь используют сепарабельные свёртки (`ndimage.correlate1d`): математически это тождественно двумерной форме (совпадение до ~1e-13), но примерно вдвое быстрее. `python tests/timing_robust.py` (256×256, 3 типа контента, 7 чередующихся раундов):

| Детектор | Медиана | К Собелю |
|---|:--:|:--:|
| Собель / Превитт | 2,6 мс | 1,0× |
| Di Zenzo, **согласованная конфиг.** (σ=0, центральные разности) | 4,9 мс | 1,9× |
| VL, 2 вектора, σ=0 | 5,8 мс | 2,3× |
| VL, 8 векторов, σ=0 | 8,5 мс | 3,3× |
| Canny | 11,5 мс | 4,5× |
| Di Zenzo, стандартная (градиенты Собеля + σ=1) | 16,4 мс | 6,4× |
| VL по умолчанию (8 векторов + перестановки) | 36,7 мс | 14,4× |

**`vector_lighting` не быстрее Di Zenzo при равных настройках.** Сравнение быстрого пресета VL со *стандартной* конфигурацией Di Zenzo даёт видимое преимущество в 2,8×, но этот разрыв — разница конфигураций (гауссово предсглаживание + градиенты Собеля против их отсутствия), а не операторов. Дайте Di Zenzo те же дешёвые настройки — и он выигрывает **по обоим показателям сразу**: в 1,17× быстрее и заметно точнее (средний F1 0,908 против 0,703 на синтетике).

Это следует из [доказательства эквивалентности](docs/equivalence.md): оба вычисляют одну и ту же величину, но тензор получает её в замкнутом виде, а виртуальное освещение восстанавливает выборкой по N направлениям. Выборка замкнутого выражения не может быть дешевле его прямого вычисления.

Ещё два замечания об измерениях:

1. **Уменьшение числа векторов даёт мало.** Время линейно с большой фиксированной частью — `T(N) ≈ 8,3 мс + 0,47 мс · N` — при N=8 фиксированные операции (градиенты, перцентиль, нормировка) составляют 69 % времени. Переход 8 → 2 вектора даёт ~1,5×, и никакое сокращение числа векторов не превысит ~1,45×.
2. **Наивный поблочный замер недостоверен** (все повторы A, затем все повторы B): идентичные вызовы дали **8,0 мс «вхолодную» против 4,0 мс после интенсивных аллокаций** — разброс в 2×, превышающий большинство сравниваемых различий. `tests/timing_robust.py` устраняет артефакт чередованием детекторов и перемешиванием порядка; `tests/timing_scaling_analysis.py` приводит декомпозицию затрат.

### Размер изображения (256 → 2048)

`python tests/testing.py --scaling`. Медиана в мс (слева) и средний F1 (справа), 3 паттерна на размер:

| Детектор | 256 | 512 | 1024 | 2048 | | F1@256 | F1@512 | F1@1024 | F1@2048 |
|---|---:|---:|---:|---:|---|:--:|:--:|:--:|:--:|
| Собель | 2,9 | 12,6 | 59 | 396 | | 0,667 | 0,667 | 0,989 | 0,989 |
| Превитт | 2,9 | 12,3 | 59 | 393 | | 0,667 | 0,667 | 0,989 | 0,989 |
| Canny | 11,9 | 49 | 207 | 1697 | | 0,653 | 0,652 | 0,652 | 0,652 |
| VL-turbo | 5,3 | 24 | 140 | 823 | | **0,990** | **0,989** | **0,989** | **0,989** |
| VL-fast | 7,5 | 32 | 171 | 1042 | | 0,945 | 0,945 | 0,927 | 0,901 |
| VL по умолчанию | 35,9 | 168 | 1056 | 9753 | | 0,947 | 0,859 | 0,759 | 0,710 |

F1 конфигурации по умолчанию **падает с ростом размера** (0,947 → 0,710), тогда как у VL-turbo остаётся постоянным. Это калибровка параметров, а не свойство оператора: `sigma=1.0` размывает фиксированную ширину в пикселях независимо от разрешения, а `binary_percentile=0.05` оставляет фиксированные 5 % пикселей, тогда как истинная доля граничных убывает как ~1/размер. **Для изображений крупнее ~512 px используйте `sigma=0–0.5` и `binary_percentile=0.0`.**

## Использование как библиотеки

Все семь детекторов имеют одинаковую сигнатуру `(H, W, 3) uint8 → (H, W) uint8`:

```python
import numpy as np
from vector_lighting import sobel, prewitt, canny, vector_lighting   # полутоновые + VL
from tests.color_baselines import dizenzo, dizenzo_canny, multichannel_sobel  # цветовые

img = np.asarray(some_PIL_image)  # (H, W, 3) uint8

# Полутоновые операторы
e_sobel   = sobel(img)
e_prewitt = prewitt(img)
e_canny   = canny(img, low_threshold=50, high_threshold=100)

# Цветовые операторы (см. tests/color_baselines.py)
e_dz      = dizenzo(img,        sigma=1.0)
e_dzc     = dizenzo_canny(img,  sigma=1.0)
e_mcs     = multichannel_sobel(img, sigma=1.0)

# vector_lighting (параметры — в vector_lighting/core.py)
e_vl      = vector_lighting(img, mode=3, sigma=1.0)
```

Для стандартного, хорошо изученного цветового детектора предпочтительнее структурный тензор Ди Дзензо — он примерно в 1.5× быстрее конфигурации `vector_lighting` по умолчанию (хотя медленнее её двухвекторного варианта), чуть точнее на реальных фото (BSDS500) и описан как baseline в литературе.
