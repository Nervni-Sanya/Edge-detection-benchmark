# Отчёт о расширенном тестировании метода Vector Lighting

**Дата:** июнь 2026 · **Скрипт:** `tests/testing.py` · **Библиотека:** `vector_lighting` v1.0.0

Отчёт отвечает на три вопроса научного руководителя:
1. Что происходит, когда линии границ параллельны виртуальным лучам освещения (диагональные границы)?
2. Как метод ведёт себя на больших изображениях?
3. Как метод ведёт себя на реальных изображениях (стандартизированный датасет)?

Все числа воспроизводимы командами из раздела «Как воспроизвести». Абсолютные времена зависят от машины; соотношения между методами устойчивы.

---

## 1. Диагональные границы и анизотропия освещения

### Теория

Вклад луча освещения **L** в отклик равен |∇·L| (модуль производной по направлению).
Он **обнуляется**, когда линия границы параллельна L (градиент перпендикулярен L). Отсюда:

- **mode=0** (один луч (1,1)): есть настоящая слепая зона — границы, идущие вдоль луча, невидимы;
- **mode≥1**: лучи идут перпендикулярными парами, худший случай — 1/√2 ≈ 0.71 от лучшего, но **никогда не ноль**;
- так как отклик использует квадраты, лучи **L** и **−L** дают одинаковый вклад ⇒ **mode=2 математически эквивалентен mode=1** (избыточен);
- **mode=3** (8 лучей: диагонали + оси) сглаживает анизотропию до ≈ ±8 %
  (отношение max/min отклика 2.614/2.414 ≈ 1.083 против 1.414 у mode=1).

- слепая зона mode=0 ровно на 135° (линии параллельны лучу (1,1)): F1 = 0.232 против 1.000 у mode≥1;
- попиксельная проверка: карты mode=1 и mode=2 **идентичны** (`np.array_equal == True`);
- провал на 0°/90° у всех детекторов (включая Sobel 0.44 и Canny) — артефакт генератора полос на осевых углах, не анизотропия.

На **изолюминантных** полосах картина та же для VL, но **Canny = 0.000 на всех 12 углах** — он не видит цветовых границ без яркостного контраста.

| VL-mode0 | VL-mode1/2 | VL-mode3 | VL-default | Sobel | Canny |

### Выводы для статьи/патента

1. Опасение про параллельные лучам границы **справедливо только для mode=0**; начиная с mode=1 слепых зон нет — это стоит указать явно (и в формуле изобретения: ≥2 неколлинеарных луча).
2. **mode=2 избыточен** — даёт байт-в-байт те же карты, что mode=1, при вдвое большей цене. Кандидат на пометку в документации.
3. **mode=3 — оптимум по изотропности** (±8 % анизотропии) — это количественное обоснование значения по умолчанию.

## 2. Большие изображения (256 → 2048)

Время (мс, медиана) и средний F1 на 3 эталонных паттернах:

| detector | 256 | 512 | 1024 | 2048 | | F1@256 | F1@512 | F1@1024 | F1@2048 |
|---|---:|---:|---:|---:|---|:--:|:--:|:--:|:--:|
| Sobel | 5.4 | 21.7 | 91.9 | 540 | | 0.667 | 0.667 | 0.989 | 0.989 |
| Prewitt | 5.4 | 21.6 | 90.6 | 539 | | 0.667 | 0.667 | 0.989 | 0.989 |
| Canny | 12.8 | 56.9 | 248 | 1233 | | 0.648 | 0.647 | 0.646 | 0.645 |
| VL-turbo | 6.0 | 26.1 | 163 | 974 | | **0.990** | **0.989** | **0.989** | **0.989** |
| VL-fast | 8.0 | 40.6 | 224 | 1329 | | 0.945 | 0.945 | 0.927 | 0.901 |
| VL-balanced | 21.3 | 106 | 751 | 4574 | | 0.945 | 0.860 | 0.759 | 0.710 |
| VL-default | 35.8 | 190 | 1096 | 10584 | | 0.947 | 0.859 | 0.759 | **0.710** |

**Главная находка:** F1 у VL-default **падает с ростом размера** (0.947 → 0.710), а у VL-turbo — стабилен (0.99). Это **артефакт параметризации, а не дефект метода**:

- `sigma=1.0` размывает границу на фиксированную ширину в пикселях; при допуске 2 px на больших кадрах размытая полоса детекции шире допуска → падает precision. VL-turbo (`sigma=0`) не страдает;
- `binary_percentile=0.05` оставляет фиксированные 5 % пикселей, а истинная доля граничных пикселей убывает как ~1/size (границы — одномерные структуры) → лишние пиксели становятся ложными срабатываниями.

**Рекомендация:** для изображений > 512 px использовать `sigma=0…0.5` и `binary_percentile=0.0` (порог по среднему) либо масштабировать percentile как `0.05·256/size`. Параметры по умолчанию откалиброваны под ~256 px.

По скорости: VL-turbo быстрее Canny на всех размерах (974 мс против 1233 мс на 2048²); VL-default масштабируется хуже (10.6 с на 2048²) — заявление «быстрее Canny» корректно только для быстрых пресетов.

## 3. Реальные изображения: BSDS500 (стандартный датасет)

**BSDS500** (Berkeley Segmentation Dataset) — общепринятый стандарт оценки выделения границ: 500 реальных фотографий, размеченных несколькими людьми. Прогнан **весь test-сплит (200 изображений)**, GT — объединение всех аннотаторов, допуск 0.0075×диагональ (стандарт BSDS), фиксированные пороги без подбора ODS/OIS — абсолютные числа ниже литературных, но сравнение между методами честное.

| detector | F1 | precision | recall |
|---|:--:|:--:|:--:|
| Canny | **0.566** | 0.482 | **0.774** |
| VL-default | 0.552 | **0.630** | 0.509 |
| Prewitt | 0.543 | 0.582 | 0.529 |
| Sobel | 0.541 | 0.577 | 0.530 |
| VL-fast | 0.530 | 0.570 | 0.517 |

**Интерпретация:** на реальных фотографиях метод **конкурентоспособен** с классикой: F1 в одной полосе со всеми (0.53–0.57), при этом у VL-default **лучшая точность (precision 0.630)** — он даёт меньше ложных границ; Canny берёт за счёт recall. Для публикации это честный результат: преимущество метода — цветовые/изолюминантные границы (раздел 1), на обычных фото он не хуже классики.

### Методологическое замечание о «стерильной» синтетике

На одиночных изолюминантных тестах Sobel может показывать высокий F1 не потому, что «видит цвет»: остаточная разница яркостей пары цветов (255,0,255)/(0,180,0) составляет ~0.3 градации серого, и после нормализации карты градиента этот микросигнал растягивается на весь диапазон — **если в кадре нет ничего сильнее**. На смешанном контенте (color_wheel: Sobel 0.51 против VL 0.887; Canny на изолюминантных полосах: 0.000) и на реальных фото преимущество цветового метода проявляется корректно. Вывод: заявления о цветочувствительности следует демонстрировать на изображениях со смешанным контентом, а не на однородных парах цветов.

## Как воспроизвести

```bash
# зависимости
pip install numpy scipy pandas pillow tqdm matplotlib openpyxl

# 1) диагонали/анизотропия (~30 с): таблицы + orientation_results.csv/png
python tests/testing.py --orientation

# 2) большие изображения (~2–4 мин): scaling_results.csv
python tests/testing.py --scaling          # или --sizes 256 512 1024

# 3) BSDS500: датасет ~70 МБ (зеркало на GitHub, без SSL-проблем Berkeley)
git clone --depth 1 https://github.com/BIDS/BSDS500 /path/to/BSDS500
python tests/testing.py --bsds /path/to/BSDS500            # весь test-сплит
python tests/testing.py --bsds /path/to/BSDS500 --bsds-limit 50   # быстрый прогон

# 4) прежние тесты: базовое сравнение + замер скорости (~15 с)
python tests/testing.py --baseline-only
```

Альтернативные датасеты, если потребуется расширить выборку: **BIPED/BIPEDv2** (250 уличных сцен, один точный аннотатор), **MDBD/Multicue** (граничная разметка, 100 сцен), **NYUDv2** (интерьеры, RGB-D). Для изолюминантных границ стандартного датасета не существует — синтетический генератор из `tests/testing.py` (полосы/звезда) закрывает эту нишу и может быть описан в статье как методика.

## Сводные выводы

1. **Диагонали:** слепая зона существует только при mode=0; mode≥1 закрывает все ориентации; mode=2 избыточен (≡ mode=1); mode=3 даёт минимальную анизотропию ±8 % — обоснование дефолта.
2. **Большие изображения:** ядро метода масштабируется корректно (VL-turbo: F1 0.99 на всех размерах, быстрее Canny); параметры по умолчанию (`sigma`, `binary_percentile`) требуют адаптации к разрешению.
3. **Реальные изображения:** F1 0.552 на BSDS500-test — в одной полосе с Canny (0.566) при лучшей precision (0.630); уникальное преимущество (изолюминантные границы, где Canny = 0.000) сохраняется.
