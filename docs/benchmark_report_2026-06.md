## 1. Ориентация границ и анизотропия освещения

### Теоретическое ожидание

Вклад одного луча освещения **L** в отклик равен |∇·L| (модуль производной по направлению) и обнуляется, когда линия границы параллельна L (градиент перпендикулярен L). Отсюда:

- **mode=0** (один луч (1,1)): ожидается слепая зона на угле 135° (линия границы параллельна лучу).
- **mode≥1**: лучи идут перпендикулярными парами. В худшем случае вклад одного из лучей пары падает до нуля, второй сохраняет полный отклик ⇒ минимальный отклик равен 1/√2 ≈ 0.71 от максимального, **не нулевой**.
- Поскольку отклик возводится в квадрат, лучи **L** и **−L** дают идентичный вклад ⇒ **mode=2 теоретически эквивалентен mode=1** (4 коллинеарные пары вырождаются в 2 уникальных направления).
- **mode=3** (8 лучей: 4 диагонали + 4 оси) сглаживает анизотропию до ≈ ±8 % (отношение max/min отклика 2.614/2.414 ≈ 1.083 против 1.414 у mode=1).

Тест с одновременным присутствием всех ориентаций (худшие направления конкурируют за общую percentile-бинаризацию с лучшими):

| VL-mode0 | VL-mode1/2 | VL-mode3 | VL-default | Sobel | Canny |
|:--------:|:----------:|:--------:|:----------:|:-----:|:-----:|
| 0.797 | 0.883 | 0.909 | 0.909 | 0.916 | 0.852 |

### Следствия

1. Слепая зона существует только при `mode=0` (один луч). При `mode≥1` и любой ориентации границы F1 ≥ 0.875.
2. `mode=2` даёт попиксельно идентичный результат с `mode=1` при вдвое большей вычислительной стоимости. Использование `mode=1` или `mode=3` предпочтительно.
3. `mode=3` минимизирует анизотропию до ±8 %, что соответствует его роли значения по умолчанию.

## 2. Масштабирование по размеру изображения (256 → 2048)

Время (мс, медиана из 2–9 прогонов) и средний F1 на трёх эталонных паттернах (checkerboard, concentric_circles, isoluminant_patches), сгенерированных для каждого размера. Команда: `python tests/testing.py --scaling`.

| detector | 256 | 512 | 1024 | 2048 | | F1@256 | F1@512 | F1@1024 | F1@2048 |
|---|---:|---:|---:|---:|---|:--:|:--:|:--:|:--:|
| Sobel | 5.4 | 21.7 | 91.9 | 540 | | 0.667 | 0.667 | 0.989 | 0.989 |
| Prewitt | 5.4 | 21.6 | 90.6 | 539 | | 0.667 | 0.667 | 0.989 | 0.989 |
| Canny | 12.8 | 56.9 | 248 | 1233 | | 0.648 | 0.647 | 0.646 | 0.645 |
| VL-turbo | 6.0 | 26.1 | 163 | 974 | | **0.990** | **0.989** | **0.989** | **0.989** |
| VL-fast | 8.0 | 40.6 | 224 | 1329 | | 0.945 | 0.945 | 0.927 | 0.901 |
| VL-balanced | 21.3 | 106 | 751 | 4574 | | 0.945 | 0.860 | 0.759 | 0.710 |
| VL-default | 35.8 | 190 | 1096 | 10584 | | 0.947 | 0.859 | 0.759 | 0.710 |

F1 у `VL-default` снижается с ростом размера (0.947 → 0.710), у `VL-turbo` — стабилен (0.99). Причина — параметризация, а не ядро метода:

- `sigma=1.0` задаёт фиксированную ширину гауссова сглаживания в пикселях; при допуске 2 px на больших кадрах ширина детектируемой полосы превышает допуск, и precision снижается. `VL-turbo` (`sigma=0`) этого эффекта не имеет;
- `binary_percentile=0.05` оставляет фиксированную долю 5 % пикселей. Истинная доля граничных пикселей убывает как ~1/size (границы — одномерные структуры), поэтому избыточно отобранные пиксели становятся ложными срабатываниями.

**Рекомендация для изображений > 512 px:** `sigma ∈ [0, 0.5]`, `binary_percentile=0.0` (порог по среднему). Альтернатива — масштабировать порог как `0.05·256/size`. Значения по умолчанию откалиброваны под ~256 px.

По времени: `VL-turbo` быстрее Canny на всех размерах (974 мс против 1233 мс на 2048²); `VL-default` масштабируется хуже Canny (10.6 с против 1.2 с на 2048²). Утверждение «быстрее Canny» применимо к быстрым пресетам, не к дефолтному.

## 3. Реальные изображения: BSDS500

BSDS500 (Berkeley Segmentation Dataset) — общепринятый стандарт для оценки детекторов границ: 500 фотографий, размеченных несколькими аннотаторами. Зеркало без SSL-проблем оригинального хоста: `https://github.com/BIDS/BSDS500`.

**Методика:** прогон по полному test-сплиту (200 изображений). Ground truth — попиксельное объединение разметок всех аннотаторов (граничный пиксель = ≥ 1 аннотатор отметил его как границу). Допуск — `0.0075·diag` (стандарт BSDS). Пороги детекторов фиксированные (без подбора ODS/OIS), поэтому абсолютные F1 ниже опубликованных в литературе; сравнение между методами в одинаковых условиях остаётся корректным.

| detector | F1 | precision | recall |
|---|:--:|:--:|:--:|
| Canny | **0.566** | 0.482 | **0.774** |
| VL-default | 0.552 | **0.630** | 0.509 |
| Prewitt | 0.543 | 0.582 | 0.529 |
| Sobel | 0.541 | 0.577 | 0.530 |
| VL-fast | 0.530 | 0.570 | 0.517 |

Все методы попадают в диапазон F1 0.53–0.57 — на реальных фотографиях `vector_lighting` сопоставим с классическими детекторами. `VL-default` обладает наивысшей precision (0.630) — меньше ложных срабатываний; Canny — наивысшим recall (0.774) за счёт ниже precision. Преимущество цветочувствительности (раздел 1) на фотографиях с естественным яркостным контрастом не даёт дополнительного выигрыша, но и не ухудшает результат.

### Замечание о синтетических тестах изолюминантности

На отдельных синтетических парах цветов (255,0,255)/(0,180,0) Sobel может показывать F1 ≈ 1.0 не из-за чувствительности к цвету, а из-за остаточной разницы яркостей пары (~0.3 градации серого), которая после нормализации карты градиента растягивается на весь динамический диапазон при отсутствии в кадре более сильного сигнала. На смешанном контенте артефакт исчезает: на `color_wheel` (синтетика, 256²) — Sobel 0.51 против VL 0.887; на изолюминантных полосах (раздел 1) — Canny = 0.000 на всех 12 углах. На реальных фотографиях BSDS500 этот артефакт также не воспроизводится.

Из этого следует, что демонстрация цветочувствительности должна опираться на изображения со смешанным контентом или комплексные тесты (полосы при 12 углах, «звезда»), а не на одиночные однородные пары цветов.

## Воспроизведение

```bash
# Зависимости
pip install numpy scipy pandas pillow tqdm matplotlib openpyxl

# 1) Ориентация / анизотропия (~30 с): orientation_results.csv + .png
python tests/testing.py --orientation

# 2) Масштабирование (~2–4 мин): scaling_results.csv
python tests/testing.py --scaling               # или --sizes 256 512 1024

# 3) BSDS500 (~70 МБ датасет, ~5–10 мин eval)
git clone --depth 1 https://github.com/BIDS/BSDS500 /path/to/BSDS500
python tests/testing.py --bsds /path/to/BSDS500           # весь test-сплит (200 изобр.)
python tests/testing.py --bsds /path/to/BSDS500 --bsds-limit 50    # быстрый прогон

# 4) Базовое сравнение и замер скорости (~15 с)
python tests/testing.py --baseline-only
```

Альтернативные датасеты для расширения выборки: **BIPED/BIPEDv2** (250 уличных сцен, один аннотатор с высокой точностью разметки), **MDBD/Multicue** (100 сцен с граничной разметкой), **NYUDv2** (интерьеры, RGB-D). Стандартизированного датасета изолюминантных границ не существует; синтетический генератор из `tests/testing.py` (`generate_orientation_dataset`, `generate_sunburst`) закрывает эту нишу и пригоден для использования в качестве методики.
